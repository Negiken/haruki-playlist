# 村上春樹プレイリスト 要件定義書

最終更新：2026-11-11

---

## 1. 目的

利用者が「いまの気分」を自由な文章で入力すると、村上春樹の小説に登場する音楽の中から、その気分に合う曲を**出典（作品名）と登場場面つき**で提案する。

* シェアハウスの住人や会社の同僚など、**知り合い数人〜十数人**が URL を教え合って使う
* 一度公開したら、以降は `main` ブランチへの push だけで**自動的にテスト・デプロイ**される

---

## 2. 前提・制約

| 項目 | 内容 |
|---|---|
| 利用者 | 知り合い数人〜十数人。ログイン不要（URL を知っていれば使える） |
| 対応環境 | スマートフォン・PC の現行ブラウザ |
| 言語 | 日本語（入力は日本語・英語どちらでも可） |
| 楽曲の範囲 | §5 の 12 作品に登場する曲のみ。カタログにない曲は提案しない |
| 音源 | 配信・再生はしない。YouTube の検索結果へのリンクだけを出す |
| 著作権 | 小説本文は引用しない。登場場面は自分の言葉で要約する。歌詞は載せない |
| 個人情報 | 入力文は保存しない。アカウント・履歴・Cookie を持たない |
| 公開先 | AWS（CloudFront → EC2 1台）。東京リージョン |
| 費用 | AWS は月 13 ドル前後。Claude API は数人利用で月数十〜数百円、1 日の上限まで使い切っても月 3,000 円以内を目安に収める |

---

## 3. 基本動作

1. 利用者がページを開く
2. テキスト欄に気分を書く（または入力例のチップを押す）
3. 「曲を選んでもらう」を押す
4. 読み取った気分の一言と、おすすめ 5 曲が表示される
5. 曲ごとに、選んだ理由・出典作品・登場場面・YouTube 検索リンク・情報の出典リンクが出る
6. 同じ文章でもう一度押すと、別の組み合わせが出ることがある（毎回まったく同じにはしない）

---

## 4. 画面仕様

画面は 1 ページで、A面（気分を書く）と B面（選ばれた一曲）を切り替える。一度に出す曲は **1 曲だけ**。

| 面 | ブロック | 内容 |
|---|---|---|
| A | 見出し | 問いかけと一文の説明 |
| A | 入力欄 | 1〜500 文字。Enter で送信、Shift+Enter で改行 |
| A | 入力例 | 4 つ。押すとその文章で即実行する |
| A | 実行ボタン | 「一曲えらぶ」。通信中は押せない |
| A | 状態表示 | 通信中「レコード棚を探しています…」／エラー時は理由を一文で |
| B | 入力した文 | 書いた気分をそのまま一行で |
| B | ジャケット | 曲のジャケット画像と、そこから出ているレコード。画像が無い曲は、原題を組んだ一色のジャケット |
| B | 曲 | ジャンル、曲名、原題とアーティスト |
| B | 出典 | 小説の書影、作品名・短編名・刊行年、場面。書影が無い作品は、題名を縦書きにした表紙 |
| B | リンク | YouTubeで探す／Apple Musicで聴く（ジャケットがある曲のみ）／情報の出典 |
| B | 「場面は要確認」 | 曲名や場面を出典で確認しきれていない曲にだけ付く（§5.3） |
| B | 戻る | 「別の気分で、もう一曲」 |
| 共通 | フッター | データの性質についての注記、画像の提供元 |

なぜその曲なのかは見せない。読み取った気分（要約・タグ）、選曲理由、選曲方法（Claude／キーワード）は API の応答には含まれるが、画面には出さない。選曲方法を確かめたいときは `/api/health` の `llm_enabled` か、応答の `engine` を見る。

B面は出典の小説ごとに決めた一色に染まる（`frontend/app.js` の `WORK_COLORS`）。

エラー時の文言：

| 状況 | 表示 |
|---|---|
| 未入力 | まず、いまの気分を書いてみてください。 |
| 500 文字超など | 気分を1〜500文字で入力してください。 |
| 短時間に連続実行 | リクエストが続いています。1分ほど待ってから、もう一度お試しください。 |
| その他の失敗 | うまく選曲できませんでした。少し時間をおいて、もう一度お試しください。 |

ライト／ダークは端末の設定に従う。

### 5.2 1曲が持つ情報

曲名（日本語）、原題、アーティスト／作曲者、ジャンル（ジャズ／ロック・ポップス／クラシック／その他）、出典作品、収録短編名（短編集のみ）、登場場面の要約、気分タグ（2〜5個）、情報の出典 URL、確認状態。

### 5.3 出典と確認状態

* 曲と場面の情報は Web 上の公開資料（主に各作品の日本語版 Wikipedia「登場する音楽」節）から収集した
* 全曲に「情報の出典」URL を持たせ、画面からたどれるようにする
* 出典で**アーティストまでしか確認できず、曲名や場面を補ったもの**は確認状態を `partial` とし、画面に「要確認」と表示する（現状は『女のいない男たち』所収「木野」の 6 曲と『1Q84』の 1 曲）
* 気分タグは編集上の判断で付けたもので、出典に基づくものではない

現在の収録数は 106 曲。データの保管はリポジトリ内の JSON ファイルとし、データベースは使わない（理由は詳細設計 §8）。

## 6. 選曲の方法

| 方法 | 使われる条件 | 内容 |
|---|---|---|
| Claude | API キーが設定済みで、1 日の上限内で、API が正常 | 文章の気分を読み取り、カタログから曲を選び、曲ごとに理由を書く |
| キーワード | 上記以外のすべて | 文章に含まれる語から気分タグを判定し、タグの重なりで選ぶ |

* Claude が使えないときは**自動でキーワード方式に切り替わり、利用者にエラーは見せない**
* どちらの方式でも、提案されるのはカタログに実在する曲だけ
* 同じ作品からは最大 2 曲まで

---

## 7. 悪用と費用の歯止め

ログインなしで公開するため、次の 2 つを設ける。

| 仕組み | 既定値 | 超えたとき |
|---|---|---|
| 同じ IP からの実行回数 | 1 分に 10 回 | エラー表示（429） |
| Claude の呼び出し回数 | 1 日に 300 回（全利用者の合計） | その日はキーワード方式で応答し続ける |

EC2 は CloudFront 経由の通信だけを受け付ける（直接アクセス不可）。

---

## 8. 非機能要件

* **自動デプロイ**：`main` への push で、テスト → インフラ適用 → 配置 → 公開 URL での動作確認まで人手なしで行う
* **安全な失敗**：テストが落ちたらデプロイしない。新しい版が起動しなければ自動で前の版に戻す
* **秘密情報**：AWS の長期アクセスキーを GitHub に置かない（OIDC）。Claude の API キーは GitHub Secrets と AWS Parameter Store（暗号化）にのみ置く
* **応答時間**：キーワード方式は 1 秒以内。Claude 方式は数秒〜十数秒を許容し、応答が無ければ最長 40 秒ほどで打ち切ってキーワード方式に切り替える
* **保守性**：選曲ロジックは Web フレームワークや外部 API に依存させず、単体テストできるようにする

---

## 9. やらないこと

* 利用者ごとのアカウント・履歴・お気に入り
* 音源の再生・埋め込み
* 12 作品以外の曲、エッセイや対談に登場する曲
* 独自ドメイン（CloudFront の既定ドメインを使う。必要になったら追加する）
